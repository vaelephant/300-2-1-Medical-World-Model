# 4. 演示流程：3–5 分钟病程预测与情景对比

> 版本：HCC World Model V1.0（research prototype，`synthetic` / `research_only`）
> 病例数据源：`apps/front/lib/demo-cases.json`（5 个精选病例，前端与本文档的单一数据源）
> 校验命令：`python -m pytest tests/test_demo_cases.py -q`

一句话定位：**看病程 → 定起点 → 做预测 → 比情景 → 查证据**。

本文档是现场讲解脚本：每一节都给出「操作 / 屏幕应看到 / 讲解词 / 不要说的话」，可以照着念。
先读第 1–4 节准备，第 5 节是主脚本，第 6–11 节是病例来源、可复现性、边界话术、故障排查、后续工作与速查卡。

---

## 1. 演示目标、时长与观众应带走的三件事

- **时长**：3–5 分钟，推荐 **4 分 30 秒**（3 分钟精简版见 §5.9）。
- **目标**：在一个具体合成患者身上，完整走一遍「历史病程 → 预测起点 → 多步预测 → 治疗情景响应 → 后续观测回顾对照 → 整体评估证据」。
- **观众应带走的三件事**：
  1. 模型不是静态打分器：选定历史时点后，它会生成**可见的未来病程轨迹**（真实权重 rollout，不是截图/占位）。
  2. 同一患者、同一起点下改变未来治疗条件，模型输出会变化；但这只是**合成模型响应实验**，不是疗效结论，也不排序推荐。
  3. 单条病例的「吻合 / 偏差」都只是回顾示例；整体性能以 **Evaluation 页**为准，当前模型**并不全面优于 Persistence**。

> 演示的胜负手不是「模型多准」，而是能把「研究原型能做什么、不能做什么」讲清楚。

## 3. 页面与区块速查

界面是「左侧边栏 + 右侧功能区」布局：左侧按功能分组，右侧只显示当前功能，不再把所有内容堆在一页。点击侧边栏即可切换；折叠后只显示图标。

| 分组 | 页面 | 地址 | 作用 |
|---|---|---|---|
| 演示工作台 | 演示总览 | `/` | 模型卡、训练曲线、checkpoint 列表、评估快照与报告列表、推理服务状态 |
| 演示工作台 | 患者病程 | `/patients` | 患者列表 + 病程时间轴浏览（备场/问答用） |

## 4. 参数先讲清楚（讲解词素材）

| 参数（页面标签） | 含义 | 建议话术 |
|---|---|---|
| 预测起点 · 随访时点 | 第 N 次随访（Day X），模型只看到这一天及以前的输入 | 「我们让模型停在第 N 次随访，Day X 之前的记录是它的输入，之后的时间轴先隐藏。」 |
| 预测未来步数 · 1–12 | 要预测的未来随访步数（预测跨度） | 「未来步数 = 预测几次随访；每一步的实际天数由模型网格决定，运行后状态行会显示步长（天）。」 |
| 基线 · 延续原条件 | 延续**输入末次随访**记录的治疗条件 | 「基线不是『什么都不做』，而是按输入最后一条随访的治疗条件继续；如果末次随访没有治疗记录，基线就是继续观察。」 |
| 情景 · 未来治疗条件 | 每个未来步固定使用同一治疗类别 | 「情景假设未来每一步都使用所选治疗，和基线共用同一起点、同一跨度。」 |
| 相对强度 0–1 | 合成假设的治疗相对强度/完成度 | 「这是 0 到 1 的相对强度，不是临床剂量、不是 mg 数、不是给药方案。」 |
| research_only / synthetic | 研究原型、合成数据标记 | 「所有输出都带 `research_only=true`、`data_source=synthetic`，不能当临床结论。」 |

**一句话讲完参数**：
> 「预测起点是第 N 次随访（Day X）；未来步数是往后预测几次随访；基线是延续末次随访的治疗条件；情景是给未来每一步固定一个治疗类别和 0–1 的相对强度。所有情景共用同一起点、同一跨度，所以可比的是模型响应，不是真实疗效。」

## 5. 主演示脚本（默认病例 SYN00733，4 分 30 秒）

**病例选择**：`SYN00733`（BCLC A，前 3 次随访内 Day 31、Day 111 两次消融，之后肿瘤直径/AFP 继续上升）。预设：预测起点 = 第 3 次随访（Day 111），未来步数 = 4，情景 = 消融 1.0 / 无治疗 0。

### 5.1 时间分配

| 时间 | 步骤 | 页面区块 |
|---|---|---|
| 00:00–00:20 | 开场与定位 | 顶部标题 + 01 |
| 00:20–00:55 | 载入精选病例 | 01 |
| 00:55–01:40 | 沿时间轴讲病程，停在预测起点 | 02 |
| 01:40–02:20 | 运行预测，看多指标未来轨迹 | 03 |
| 02:20–03:10 | 切到「治疗情景」页，2 个未来条件同屏比较 | 治疗情景 |
| 03:10–03:55 | 揭示后续观测，讲吻合与偏差 | 治疗情景 |
| 03:55–04:30 | 去评估页看整体证据与边界 | 模型评估 |

### 5.2 第 1 步 · 开场与定位（00:00–00:20）

- **操作**：停在 `/world-model` 顶部，不点任何东西，先让观众看到左侧边栏。
- **屏幕应看到**：左侧边栏（按「演示工作台 / 世界模型 / 模型证据」分组，当前「病程预测」高亮）；标题「World Model · 病程预测」；「01 · 精选演示病例」5 张卡片。
- **讲解词**：
  > 「这是一个研究原型，不是临床系统。今天只用一位合成患者，走完『看病程—定起点—做预测—比情景—查证据』。所有数据都是本地生成的合成 HCC 队列，输出带 `research_only`。我们关心的是世界模型如何表示病程，以及它在哪里会错。」
- **不要说的话**：×「我们的模型能预测肝癌」×「准确率很高」×「可以辅助临床决策」。

### 5.3 第 2 步 · 载入精选病例（00:20–00:55）

- **操作**：在「01 · 精选演示病例」卡片区点 `SYN00733` 卡片（或卡片底部「载入病例」）。
- **屏幕应看到**：
  - 该卡片高亮；参数区下方出现患者信息：「SYN00733 · 男 · 59 岁 · BCLC A · Child-Pugh A · 诊断日 2024-11-28 · 精选合成病例」；
  - 02 时间轴加载出来；预测起点自动变为「第 3 次 · Day 111」，未来步数 = 4；
  - 03 预测结果区暂时为空；页面底部有「下一步 · 比较治疗情景」（运行预测后才可点）。
- **讲解词**：
  > 「病例是从本地合成队列里按 BCLC 分期、已记录治疗和轨迹形态人工挑的，**没有按模型预测效果挑**。这位是 BCLC A，前三次随访里 Day 31、Day 111 两次消融；但肿瘤直径从 3.0 → 3.2 → 5.4 cm、AFP 从 96 → 118 → 169，治疗事件之后指标还在恶化——这让它适合讲『治疗事件和指标变化的关系』。」
- **不要说的话**：× 不要把它说成真实患者/真实医院数据 × 不要下「消融治疗失败」这类医学结论（数据是合成的） × 不要在这里一次讲完全部参数（留到后面步骤内嵌讲）。
- **操作提示**：切换病例请用 01 卡片；上方患者下拉框只加载前 500 位患者，精选病例（如 `SYN00733`）不在列表中时不会显示，载入后才会作为当前项出现。

### 5.4 第 3 步 · 沿时间轴讲病程，停在预测起点（00:55–01:40）

- **操作**：在 02「病程时间轴」点第 3 次随访（Day 111）；或在「预测起点 · 随访时点」下拉选「第 3 次 · Day 111」；确认「预测未来步数」= 4。
- **屏幕应看到**：被选中的随访行高亮为**输入终点**；第 3 次之后的随访记录默认隐藏，表格折叠为一行「已隐藏 N 次后续观测」（可展开为“待揭示”占位）；时间轴里能看到治疗事件标记。
- **讲解词**：
  > 「时间轴把随访、观察指标和治疗事件排在一起。我们停在第 3 次随访 Day 111——注意，Day 111 的消融也包含在输入里，模型只看到这一天及以前。**预测起点 = 第 3 次随访（Day 111）**。之后的记录先隐藏：既不把未来信息泄漏给模型，也让观众先别看到答案。」
  >
  > 「**未来步数 4** 表示往后预测 4 次随访的跨度。步长不是固定 30 天，运行后状态行会显示模型实际使用的天数。」
- **不要说的话**：×「模型记住了后面的数据」 × 不要提前揭示后续观测（此时「揭示后续观测」按钮还不可用，必须先运行）。
- **可选动作**：点一下第 4 次随访再点回第 3 次，说明「起点可以换，换起点会清空已有预测，避免不同起点结果混在一起」。

### 5.5 第 4 步 · 运行预测，看多指标未来轨迹（01:40–02:20）

- **操作**：点「运行病程预测」。
- **屏幕应看到**：
  - 短暂「计算中…」后出现状态行，例如：「输入 3 次随访 · 预测起点 Day 111 · 步长 55.5 天 · hcc-wm-mvp-0.2-residual」；
  - 状态行下方出现 4 个「末步预测概览」KPI 磁贴（基线末步值 + 相对输入末次观测的 Δ；Δ 仅方向提示，不代表疗效，模型无置信区间）；
  - 四张图出现（肿瘤直径 cm / AFP ng/mL / 白蛋白 g/L / 总胆红素 μmol/L），四图共用上方 1 个图例，只有第一张图在起点竖线上标「预测起点」；
  - 页面下方出现「预测末步结果 · Day …」表格（当前只有基线一行）与「下一步 · 比较治疗情景」按钮。
- **讲解词**：
  > 「基线 = 延续输入末次随访的治疗条件。这里末次是 Day 111 的消融（相对强度 0.765），所以基线不是『不治疗』，而是『按原条件继续消融』。」
  >
  > 「模型在没看到 Day 111 之后任何数据的情况下，给出未来四步的肿瘤直径、AFP、白蛋白、总胆红素。这些是**合成模型响应**，不是临床预测。」
- **不要说的话**：× 不要念具体数值并断言「会恶化到多少」 × 不要用「预测准确」 × 不要此时展开多步误差/校准（留到 05）。
- **应急话术**：若曲线看起来异常（例如数值快速漂移），不要掩饰，直接说：「合成模型的多步输出会漂移，这也是我们后面要看 Evaluation 多步误差的原因。」

### 5.6 第 5 步 · 2 个未来治疗条件同屏比较（02:20–03:10）

- **操作**：点「下一步 · 比较治疗情景」进入 `/simulation`（也可用左侧边栏「世界模型 → 治疗情景」）。确认顶部「已带入的预测条件」仍是 `SYN00733`、第 3 次 Day 111、未来步数 4；在 04 治疗情景确认情景 1 = 消融 / 1.0，情景 2 = 无治疗 / 0；点「比较基线与 2 个情景」。
  > 按钮文案会按当前情景数变化（如「比较基线与 2 个情景」）；本病例预设 2 个情景 + 基线。要同屏比较 3 个情景，可在 `/world-model` 载入 `SYN00364` 或 `SYN00614` 后再进入本页（见 §6）。
- **屏幕应看到**：
  - 页面标题「Simulation · 治疗情景对比」；顶部显示从上一页带入的患者/起点/步数；
  - 比较后四张图新增情景曲线，图例含「基线 · 延续原条件」与「情景 1 · 消融 (1)」「情景 2 · 无治疗 (0)」；
  - 「预测末步结果」表格从 1 行变为 3 行（基线 + 2 情景）；
  - 若失败会出现红色「请求失败」提示框。
- **讲解词**：
  > 「同一起点、同一预测跨度，只改未来治疗条件：情景 1 假设未来每一步都是消融、相对强度 1.0；情景 2 假设未来每一步都不治疗（强度 0）。基线继续末次随访的原条件，所以基线可能和情景 1 接近但不完全一样——这是把末次随访的治疗向量原样延续，而不是重新设定。」
  >
  > 「这展示的是**模型对治疗条件的响应**。相对强度 0–1 是合成假设的强度，不是临床剂量；曲线的高低、顺序**不表示疗效排名**，我们不能从这张图推荐『继续消融』或『不治疗』。」
- **不要说的话**：×「这个治疗更好/更差」 ×「模型推荐继续消融」 ×「曲线越高说明疗效越差」 × 不要把相对强度说成 mg / mg/kg / 真实给药剂量 × 不要把曲线排序包装成「最优方案」。

### 5.7 第 6 步 · 揭示后续观测，讲吻合与偏差（03:10–03:55）

- **操作**：点「揭示后续观测」。
- **屏幕应看到**：四张图出现**灰色后续观测点**（原轨迹 Day 150、Day 212…）；图表上方出现「回顾对照，不是替代情景验证」提示框；按钮变为「隐藏后续观测」。
- **讲解词**：
  > 「现在把原轨迹的后续观测叠上来。注意：这是**同一条合成轨迹**的后续，不是任何一个替代情景的真实结局；灰色观测的日期也可能和预测网格不完全对齐，所以不要拿不同日期直接相减当误差。」
  >
  > 「先看吻合，再看偏差：这个病例 Day 150 肿瘤直径短暂回落后继续上升，模型有没有抓住转折？单条病例的吻合不能证明模型整体好，偏差也不能证明它没用——都要回到评估页看整体。」
- **不要说的话**：×「模型预测准确」（单条吻合 ≠ 准确率） ×「这条曲线证明治疗有效」 ×「灰色观测就是替代情景的结局」 × 不要只展示吻合、隐藏偏差。

#### 偏差话术预案（按 Lead 指定，务必提前预演）

> 只在观众追问或时间充裕时展开；每讲完一个偏差，落回「所以要看整体指标，不能把单条曲线当验证」。

| 病例 | 预演观察（本机当前权重） | 用法 | 建议话术 |

## 7. 数据来源与可复现性

- **队列**：`artifacts/synthetic/` 由本地脚本生成，默认 `n=1000`、`seed=42`、`max_visits=12`；生成命令见 [0-快速启动.md](0-快速启动.md)「生成测试数据」与 [3-训练命令.md](3-训练命令.md) §2。产物含每位患者一个 `SYN*****.json` 和 `manifest.json`。
- **权重**：`artifacts/models/mvp/best.pt`，由 `scripts/train_world_model.py` 产出；命令与参数见 [3-训练命令.md](3-训练命令.md) §3.1。
- **评估报告**：`reports/eval_mvp.json`，由训练结束时的评估或 `scripts/evaluate_model.py` 生成；见 [3-训练命令.md](3-训练命令.md) §4。
- **不入库**：`artifacts/*`、`reports/*` 与 `*.pt` 已在 `.gitignore` 中。换台机器需要自己生成数据和训练（不要复制别人机器上的权重）。
- **配置**：`configs/data.yaml` 是初始配置草稿（`seed: 42`，但 `patients: 10000` 是规划量）；演示/校验以本地 `artifacts/synthetic` 的 `manifest.json` 为准（当前 1000 人，12 次随访）。
- **重新生成数据后**：患者 ID 可能变化，曲线数值也会变。必须同步更新 `apps/front/lib/demo-cases.json`，再运行：

  ```bash
  python -m pytest tests/test_demo_cases.py -q
  ```

  该测试校验 JSON 结构、`source.doc` 是否存在，以及（`artifacts/synthetic` 存在时）每位病例的患者文件存在、随访数 ≥ `context`、前 `context` 次随访至少有一次治疗记录。**`artifacts/` 缺失时患者数据校验自动 skip**，结构校验仍执行。
- **合成数据边界值**：生成器对特征做了工程裁剪（如白蛋白下限 5 g/L、肿瘤直径上限 50 cm 等）。页面出现贴边值（例如某些病例白蛋白长期 5.0）是生成器边界，不是临床信号，**不要做临床解读**。

## 8. 边界与话术（必须背下来）

| 议题 | 不要这样说 | 建议这样说 |
|---|---|---|
| 研究定位 | 「临床决策系统」「可辅助诊断」 | 「研究原型（research prototype），输出带 `research_only=true`，不是临床结论。」 |
| 数据来源 | 「真实患者数据」「医院数据」 | 「本地生成的合成 HCC 队列（seed 42, n=1000），不含真实患者信息。」 |
| 原轨迹后续观测 | 「预测验证」「真实结局验证」 | 「只能做**回顾对照**；随访日期可能与预测网格不同，后续治疗也可能变化，不能直接当误差或疗效验证。」 |
| 替代治疗情景 | 「这个方案有效 / 更优」 | 「替代情景没有对应真实结局，只展示**模型响应**，不能证明有效，也不能用原轨迹去验证它。」 |
| 曲线排序 | 「推荐继续消融」「最优方案」 | 「仅按输入情景顺序展示，**不排序、不推荐**；相对强度也不是临床剂量。」 |
| 单条病例 | 「模型预测准确」 | 「单条回顾示例；整体性能以 Evaluation 页为准，模型当前并不全面优于 Persistence。」 |
| 整体性能 | 只报排除 AFP 的指标 | 「总体 MAE / 宏平均未超过 Persistence，仅排除 AFP 后在合成测试集上略好；AFP 逐特征误差更大。」 |
| 影像 / 风险头 / 不确定性 | 暗示已有 CT 分析、风险评分或置信区间 | 「影像编码、风险头训练、不确定性校准本期未完成；当前 `uncertainty` 为空，不应解读为置信区间。」 |
| 真实使用 | 「下一步就能上临床」 | 「下一步是接合法授权的纵向 HCC 数据做外部验证，再谈临床研究。」 |
| 现场操作 | 现场训练 / 现场改病例参数 | 「演示用固定精选病例与预设参数；参数解释已在文档中准备好。」 |

### 8.1 常见追问与回答

- **「这个患者后面会怎样？」** → 「模型给出的是研究输出；我们同时展示原轨迹后续作回顾对照，取舍要回到评估页的整体指标。」
- **「哪个治疗最好？」** → 「我们不能排序，也不能给治疗建议。这里只能比较模型在不同未来治疗假设下的响应；替代情景没有真实结局。」
- **「能上临床吗？」** → 「不能。合成数据 + 研究原型，缺真实纵向验证与校准。」
- **「为什么预测和实际不一样？」** → 「单条轨迹有偏差很正常；模型学的是群体趋势。请看多步 rollout 误差和逐特征误差。」
- **「AFP 误差为什么这么大？」** → 「AFP 量级大，会主导含 AFP 的 MAE；我们同时看排除 AFP 的宏平均和逐特征表。」
- **「能用影像/风险评分/不确定性吗？」** → 「本期未完成，已在后续工作中列出。」
- **「数据是真实的吗？」** → 「不是，是合成生成器按种子生成的；病例 ID 和数值都会随重新生成变化。」

## 11. 一页速查卡（可打印 / 贴在屏幕边）

**演示前**：API 8000 已起（`/health` ok）→ 前端 3000 已起 → `/world-model` 无报错 → 提前跑一次预测 → `/simulation` 跑一次比较 → `/evaluation` 有报告。

**主流程（默认 SYN00733，左侧边栏切换页面）**：

1. `/world-model`：01 卡片点「载入病例」→ 讲患者与两次消融 + 指标恶化。
2. 02 时间轴点第 3 次随访（Day 111）→ 讲「模型只看到这天及以前」，未来步数 4。
3. 03 点「运行病程预测」→ 讲基线与四个指标的未来曲线。
4. 点「下一步 · 比较治疗情景」→ `/simulation`：04 点「比较基线与 2 个情景」→ 讲 2 个未来治疗条件、0–1 相对强度，**不排序**。
5. 同页点「揭示后续观测」→ 讲回顾对照（灰色 = 原轨迹后续，不代表替代情景结局）。
6. 侧边栏「模型评估」→ `/evaluation` → 讲三个汇总指标 + 多步误差 + 合成数据边界。

**三句必须说的边界**：

- 「研究原型 + 合成数据，输出 `research_only`，不是临床结论。」
- 「替代情景没有真实结局，不能证明有效；曲线顺序不是推荐。」
- 「单条病例的吻合/偏差只是回顾示例；整体指标显示模型并未全面优于 Persistence。」

**三句绝对不说**：

- ×「模型预测准确 / 准确率 X%」
- ×「这个治疗更优 / 推荐该方案」
- ×「可以用于临床」
