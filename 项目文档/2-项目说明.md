## **一、首先确定世界模型要学习什么**

第一版不要同时做肝癌诊断、影像分割、生存预测、治疗推荐、病理生成和临床问答。

建议只训练三个核心能力。

**能力一：患者状态表示（State Representation）**

将历史检验、肿瘤状态、治疗事件及可选影像特征编码为统一患者隐状态 (z_t)。

**能力二：疾病状态演化（State Transition）**

学习从当前状态到未来状态的转移，支持按时间间隔进行多步 Rollout。

**能力三：未来风险预测（Risk Forecasting）**

输出未来 30/90/180 天的模拟疾病状态、预定义恶化事件风险及预测不确定性。

### **世界模型数学定义**

定义患者在时间 (t) 的状态：

[ s_t=(x_t,m_t,a_t,\Delta t) ]

其中 (x_t) 为临床特征，(m_t) 为缺失掩码，(a_t) 为治疗事件，(\Delta t) 为时间间隔。

模型学习：

[ z_t=E\theta(s{\leq t}) ]

[ p\theta(z{t+1}\mid z_t,a_t,\Delta t) ]

[ p\theta(x{t+1},y{t+1}\mid z{t+1}) ]

建议使用概率状态转移模型，而不是只输出一个确定的未来数值。这样才能展示多条可能的未来轨迹和不确定性。

## **五、训练任务与验收标准**

这里最重要的是避免出现一种情况：模型在合成数据上取得 95% 的准确率，但实际上只是学会了我们自己编写的数据生成规则。

因此，建议设置四层验证。

模型验收矩阵

| **验证层级** | **通过标准**                                  |
| -------- | ----------------------------------------- |
| 工程正确性    | 训练无 NaN、固定种子可复现、模型可加载、推理接口通过测试            |
| 单步预测     | 关键连续指标 MAE/RMSE 优于 Persistence 基线，按指标逐项报告 |
| 多步演化     | 报告 30/90/180 天误差，比较 GRU 基线，且不存在明显数值发散     |
| 风险与不确定性  | 报告 AUROC、AUPRC、Brier、区间覆盖率和预测区间宽度         |
| 跨生成器泛化   | 使用未参与训练设计的第二套模拟参数与生成机制，报告性能下降幅度           |
| 真实数据适用性  | 明确标记“尚未完成真实临床纵向验证”，不以合成指标替代临床证据           |

建议把以下目标作为**工程验收门槛**，而不是承诺的临床性能：

- 测试集预测流程成功率 100%，不出现崩溃或非法数值。
- 对选定的主要连续指标，世界模型在固定合成测试集上的误差优于简单基线；若没有改善，必须在报告中如实说明。
- 90% 预测区间在合成测试集上的经验覆盖率目标为 85%–95%，同时报告区间宽度，防止靠极宽区间达标。
- 100 次采样的单患者预测，在演示设备上目标耗时不超过 3 秒。
- 同一模型版本、输入和随机种子，能够重现相同结果。

### **建议重点训练的三个实验**

**Experiment 01 · State Reconstruction**

基础

从部分历史随访重建被遮蔽的临床指标，检查模型是否编码了患者状态信息。

**Experiment 02 · Future Rollout**

核心

从第 3 次随访开始预测后续 6 次状态，比较真实合成轨迹与预测轨迹。

**Experiment 03 · Conditional Simulation**

展示

在相同患者状态下改变模拟治疗事件，观察不同条件下的未来轨迹分布。明确标注这只是对合成生成机制的学习。

## **六、公开数据怎么利用？**

由于没有医院真实数据，我建议把公开数据分成三个用途，不能把不同数据集随意拼接成患者的连续病程。

| 数据来源                                         | 适合任务             | 限制               |
| -------------------------------------------- | ---------------- | ---------------- |
| The Cancer Imaging Archive (TCIA)            | 肝脏 CT/MRI、影像编码实验 | 不保证具有完整纵向治疗与结局记录 |
| The Cancer Genome Atlas (TCGA) LIHC          | 肝癌分子特征、部分临床结局探索  | 不适合直接当作完整随访轨迹    |
| UCI Machine Learning Repository HCC Survival | 表格风险预测基线实验       | 样本量小，且不是纵向世界模型数据 |

对应入口：

- [TCIA 医学影像数据](https://www.cancerimagingarchive.net/?utm_source=chatgpt.com)
- [NCI GDC / TCGA 数据门户](https://portal.gdc.cancer.gov/?utm_source=chatgpt.com)
- [UCI 数据集目录](https://archive.ics.uci.edu/?utm_source=chatgpt.com)

这些是可调查的数据来源，不代表已经核实每个数据集的访问权限、字段完整性或训练适用性。

建议在 D03–D05 期间先生成完整合成数据，不等待公开数据下载。公开数据用于独立的特征提取或基线实验，不能把静态数据的结果宣称为纵向疾病演化验证。

## **八、项目风险与降级策略**

| 风险               | 应对方案                                        |
| ---------------- | ------------------------------------------- |
| macOS 训练速度不足     | 先使用 2,000 条轨迹调试，正式训练再扩展到 10,000 条；必要时租用 GPU |
| 世界模型效果不如 GRU     | 保留 GRU 作为可演示基线，不伪造模型优势                      |
| 公开数据下载或授权延迟      | 不阻塞合成数据主线                                   |
| CT/MRI 编码器无法及时接入 | 影像模块标为实验性，不影响核心演示                           |
| 多步预测数值发散         | 缩短预测窗口、加入状态约束和梯度裁剪                          |
| 治疗情景结果不可信        | 明确展示模拟假设，不宣称真实治疗获益                          |
| 演示现场网络故障         | 本地运行全部服务，预加载模型与演示患者                         |
