# DR.SEEK 多病种医疗世界模型开发规划

规划日期 2026-11-24 · 首期 HCC 研究演示目标 2026-12-21

## 1. 产品目标与开发顺序

在给定患者历史和预测起点时，模型输出未来状态分布，并允许研究人员指定未来条件、比较模型响应。以肝细胞癌（HCC）完成可复现的纵向预测闭环，再用第二病种验证平台复用。第一版允许各病种分别训练、评估和发布。只有在独立病种评估显示有收益时，才立项共享编码器或联合训练。

| 范围 | 交付 |
| --- | --- |
| 首期 HCC | 结构化纵向数据、真实模型权重推理、连续状态多步预测、固定条件模拟、可复现评估和五页演示 |
| 第二病种 | 优先评估肺结节随访，按纵向数据可用性、标签和队列完整性决定是否启动 |
| 后续 | 获得可用纵向数据后开展回顾性外部验证。影像、事件风险、联合训练分别按数据和评估门槛推进 |

## 2. 仓库基线

按主分支 README，已有合成轨迹、训练与评估、权重推理 API 和五个前端页面。当前治疗模拟以固定未来治疗条件为输入，适用范围是合成环境中的模型响应实验。影像、风险头训练及不确定性校准仍待完成。第一周应实际跑通链路并记录版本和结果；上述状态来自仓库文档。继续使用现有目录、PyTorch 训练链路、FastAPI 与 Next.js。旧 ICU 原型保留在 `v-1/`。本规划承接[现有 HCC 项目说明](../../项目文档/2-项目说明.md)。

## 3. 平台和病种的职责

| 现有模块 | 平台通用职责 | HCC 首期职责 |
| --- | --- | --- |
| `packages/data` | 患者事件时间轴、观测可用时间、单位、缺失掩码、来源、数据版本与队列切分 | 肝功能、肿瘤负荷、治疗事件、结局口径、纳排标准和合成生成规则 |
| `packages/world_model` | 历史编码、时间间隔感知的状态转移、观测解码和任务头接口 | HCC 特征字典、预测目标、治疗条件编码和病种权重 |
| `packages/training` | 滚动预测、基线对照、指标、区间校准与复现实验 | 指标优先级、预测窗、缺失与删失规则、亚组定义 |
| `apps/back` | 按病种和版本加载产物，校验输入，输出来源和运行状态 | 支持的字段、预测窗与可选条件；沿用现有 forecast 和 simulate 入口 |
| `apps/front` | 患者时间轴、预测与观测分层展示、条件对照、版本和评估页 | HCC 字段名称、单位、展示范围与演示病例 |
| `packages/imaging` | 影像特征扩展接口 | 首期可选。具备可靠配对数据后，先验证结构化基线加影像特征的增益 |

首期在现有模块边界内集中管理病种配置。接入第二病种时，以两条真实接入路径决定公共接口，无需提前建设独立的插件服务。

## 4. 数据、模型与评估合同

1. **时间轴与切分。** 每条事件记录患者标识、发生时间、可用时间、来源和单位。以最后一个可用输入观测作为预测起点，输入可用时间须不晚于该起点。治疗历史和未来条件分别记录，未来观测只参与标签和回顾评估。按患者切分，预处理仅在训练集拟合。对真实队列优先保留时间外或机构外的测试队列。
2. **训练优先级。** 固定现有可运行模型和数据切分。建立末次观测延续基线及可比的序列基线，使用同一输入窗口、预测窗和标签。优先交付关键连续状态的单步和多步预测；按 30、90、180 天分别报告误差、有效样本量及覆盖条件。预先确定观测匹配容差，不以插值补作真实标签。分布预测就绪后，使用验证集校准并报告测试集经验覆盖率和区间宽度。事件风险头在事件定义、删失规则和有效样本量明确后另立任务。
3. **证据分层。** 合成同分布测试验证工程闭环，独立生成配置验证对生成机制变化的敏感性。公开数据按其字段、许可和纵向结构选择独立任务。真实纵向泛化需要经过授权且可追溯的外部队列。各数据来源单列报告和结果，禁止将跨来源患者拼接成轨迹。
4. **产物与接口。** 每次交付记录数据与切分版本、特征字典版本、模型权重标识、预处理、校准状态、配置、随机种子和评估报告。推理返回预测起点、时间窗、数据来源、模型版本与 `research_only=true`。输入缺项或产物版本不匹配时返回可解释状态。固定条件模拟复用同一历史，记录未来条件和随机种子，结果标注为研究情景响应。
5. **展示口径。** 时间轴区分历史观测、预测和回顾观测，评估页展示基线、样本量与数据来源。区间仅在相应能力可用时展示，并明确校准状态。数据进入医院验证流程后，使用经授权的受控环境，公开仓库仅提交文档、代码与可公开的配置及汇总结果。

## 5. 研发排期与负责人

| 时段 | 牵头角色 | 工作包与验收产物 |
| --- | --- | --- |
| 11.24–11.29 | 数据、算法 | 固定当前训练和推理基线；输出数据字典、预测起点规范、患者切分清单和端到端运行记录 |
| 11.30–12.06 | 算法 | 完成基线复跑、多步指标表、独立生成配置测试；报告各预测窗的误差、样本量、失败病例和限制 |
| 12.07–12.13 | 后端、前端 | 接通同一版本的权重、API 和五页演示；验收缺失输入、模型不可加载和条件切换，确保页面与评估报告一致 |
| 12.14–12.21 | 研发负责人、医学顾问 | 冻结演示版本，复跑训练到推理，审核演示口径；交付启动说明、固定演示病例、评估报告及已知限制 |
| 首期之后 | 数据负责人、病种专家 | 调查第二病种数据并形成接入评估，签定标签、预测窗和队列口径后开始接入 |

角色可兼任。影像、事件风险与区间校准可以并行探索，演示只开放已通过对应验收的能力。

## 6. 发布与扩展门槛

- **工程发布。** 干净环境能复跑数据生成、训练、评估及权重加载。固定数据与版本可重现结果到约定数值容差。固定测试队列可批量推理，时间顺序、单位和缺失处理通过检查。端到端演示只能读取明确标识的权重和数据版本。
- **模型结论。** 冻结测试集前确定主指标、基线及通过标准。全部时间窗保留基线比较与失败样本记录。若主要预测目标未优于基线，展示实测结果并将结论限定为工程演示。校准或数据覆盖未达门槛时，对应区间或预测窗在界面降级。
- **演示验收。** 演示至少覆盖历史时间轴、多步预测、固定条件对比和评估回看。公开数据实验缺乏合适数据时记录所缺字段和进度，将其保留为独立验证任务。演示统一标注研究用途。
- **第二病种接入。** 通过数据字典与映射、跨时间观测质量、目标事件定义和样本规模的评审后，先走通独立基线到评估发布。验证训练入口、推理入口和时间轴页面可复用，模型、队列、指标和版本按病种独立追踪，同时回归验证 HCC 流程。
- **真实数据阶段。** 先确定数据使用范围、去标识处理、独立队列切分及评估方案，再做回顾性外部验证。临床工作流试点应另行立项，独立审查使用场景与证据要求。

## 7. 启动事项

- 研发负责人确认首期演示用例与各角色负责人。
- 数据和算法负责人共同冻结 HCC 数据字典、观测时间定义、预测目标及基线对照方案。
- 全栈负责人用固定患者和版本做一次端到端回归，记录失败和缺口，作为首周任务清单。
